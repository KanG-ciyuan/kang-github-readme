## Keep

- Reader-centered first-screen value rather than internal implementation detail.
- Natural-language usage examples and concrete output descriptions.
- Honest evidence labels and explicit troubleshooting.
- Dynamic structure rather than a universal README template.

## Adapt

- Generalize the Meta Skill README method to products, applications, libraries, APIs, CLI tools, templates, research projects, and private repositories.
- Convert selective frontend improvement into a documentation scope lock with numbered `preserve / rewrite / add / remove` items.
- Separate README edits, asset changes, repository metadata, and publication into independent authorization scopes.

## Reject

- Copying a fixed section order into every repository.
- Treating badges, screenshots, or bilingual content as universal requirements.
- Publishing owner-local installation state, private backup rationale, or unverified capability claims.
- Automatically editing GitHub metadata or pushing changes as part of a documentation-only request.

## Original Contributions

- A fact ledger separating `verified`, `historical`, `to verify`, and `do not publish` claims.
- Stable preview item identifiers and per-item approval.
- A section-level scope lock that prevents unapproved adjacent edits.
- Public-versus-private reader strategy without weakening secret controls.
- Staged inspection for large repositories and honest external-link status.
