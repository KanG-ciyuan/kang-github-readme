## Candidate-Specific Lessons

- Lead with reader value rather than maintainer-local workflow details.
- Use natural-language examples and concrete outputs.
- Match structure and evidence to project type instead of forcing one template.
- Separate design advantages from validated behavior.

## Deliberate Rejections

- A universal README section order.
- Automatic README writes before a representative preview.
- Treating visual assets, GitHub metadata, or publication as part of README approval.
- Publishing local installation state, backup rationale, private paths, or unsupported claims.
- Reporting recorded fixtures as provider-backed model performance or human preference.

## Original Contributions

- Stable preview identifiers with item-level accept, revise, defer, and reject decisions.
- A section scope lock that prevents silent adjacent edits.
- A four-state fact ledger for public claims.
- Public and private reader modes without weaker secret controls.
- Staged large-repository inspection with named evidence gaps.
- Separate permission domains for README, assets, metadata, and publication.

## Design Advantages

- Dynamic project modules reduce fixed-template behavior.
- Representative previews make direction and scope reviewable before a write.
- Fact and permission boundaries reduce unsupported public claims and unauthorized external changes.
- Incremental mode supports both first-time creation and repeated README iteration.

## Hypotheses

- Users may need fewer full rewrites when representative previews are shown before editing.
- Project-specific modules may produce clearer READMEs than a universal template.
