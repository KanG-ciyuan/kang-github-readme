# Kang GitHub README

> 先读懂仓库，再把 README 写成符合项目、证据和读者的公开介绍。

`kang-github-readme` 是由 **Kang** 创建并维护的 GitHub README 设计与审核 Skill。它适用于新仓库首次编写，也适用于已有 README 的选择性优化。

## 核心方式

- 先分析项目类型、目标读者和可验证事实。
- 先展示结构和关键文案预览，确认后才修改。
- 对现有内容执行保留、改写、新增和删除判断。
- README、视觉素材、GitHub 元数据和发布分开授权。
- 不把密钥、私人路径、内部备注或未验证能力写入公开仓库。

## 你可以这样说

- “先分析这个 GitHub 项目，给我 README 结构和首屏文案预览。”
- “只优化 README 的简介，其他章节不要动。”
- “审计这个 README 里的命令、链接和功能声明，先不要修改文件。”
- “检查 README 和 GitHub Description、Topics 是否一致，分开给我建议。”

## 证据边界

当前仓库只包含本地开发证据。公开发现、安装、模型实跑和人工盲评均尚未验证，不作为当前能力声明。
