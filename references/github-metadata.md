# GitHub Metadata

Read this reference only when the user requests repository Description, Topics, homepage, social preview, or publication consistency.

## Proposal Rules

- Keep Description concise, literal, reader-centered, and consistent with the README opening.
- Choose Topics from verified technology, domain, and use-case facts. Do not add popularity or maturity claims as topics.
- Recommend a homepage only when the destination is verified and useful to repository readers.
- Recommend a social preview only when it reflects the real project. Do not fabricate product UI or reuse another brand's identity.
- Identify contradictions between README, Description, Topics, homepage, and social preview before proposing changes.

## Permission Boundary

Reading visible metadata and proposing text do not authorize an external write. Require separate confirmation before changing Description, Topics, homepage, social preview, or any other GitHub setting.

README approval does not authorize metadata changes. Metadata approval does not authorize asset upload, commit, Pull Request, merge, release, deploy, or default-branch push.

When publication is explicitly requested, use the agreed feature-branch and review workflow. Authentication or permission failure must leave the local deliverable intact and be reported as incomplete external state.
